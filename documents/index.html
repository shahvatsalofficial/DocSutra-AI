    What it catches

    The problems readers hit first

    Most link checkers stop at "does the URL exist". DocSutra checks what actually goes wrong in real documentation sets.

    Links and anchors

    Every relative link and every #heading anchor is resolved against the real filesystem, with GitHub slug rules and case-sensitivity checks.

    Leaked credentials

    Known token formats are detected and redacted before they reach any report, so the report is safe to share.

    Commands that still exist

    Documented flags and subcommands are compared to a CLI contract you declare. Risky snippets like curl | sh are flagged, never run.

    Accessibility basics

    Missing alt text, empty link text and skipped heading levels, with WCAG pointers.

    Safe by design

    Read-only. No network. No command execution. Symlinks skipped. Hostile documents stay inert data.

    Reports people read

    Self-contained HTML, Markdown, JSON and SARIF, each with a verification ledger and a not-checked section.

    How it works

    One command, four reports

    Files in, evidence out. Every stage is deterministic, and the report states what was never checked.

    1. 1

      Scan

      Point it at a folder.

      npx docsutra-ai scan --root .
    2. 2

      Read

      Open the HTML report. Findings show line, context and fix.

      .docsutra/audit.html
    3. 3

      Gate

      Fail pull requests only on new problems.

      docsutra scan --baseline base.json

    FAQ

    Quick answers

    Does it need an API key or internet?

    No. The scan is fully offline and uses only Node.js built-ins.

    Will it run the commands in my README?

    Never. Commands are classified and compared to a contract only.

    Does a green report mean my docs are correct?

    No. It means the listed static checks passed. Read the ledger and the not-checked section.

    How accurate is it?

    It scores 100% precision and recall on the author-built labelled corpus. That is regression evidence, not a guarantee for arbitrary repositories.

    Can I use it commercially?

    Yes, under Apache-2.0.
