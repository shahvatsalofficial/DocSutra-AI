# Public release checklist

- [ ] Confirm proposed DocSutra brand is not in conflict with an existing Docsutra product; review naming and trademarks.
- [ ] Verify desired GitHub owner, npm namespace and domain availability; do not invent links.
- [ ] Review third-party licenses and README examples; keep license text accurate.
- [ ] Run actual Windows, macOS and Linux CI and report versioned evidence.
- [ ] Threat-model external tools and document privacy constraints.
- [ ] Verify installed skills are discoverable in each claimed IDE; CLI copy is insufficient.
- [ ] Keep community governance, contribution and private security disclosure process public.
- [ ] Run clean install, CLI demo, server auth test, negative test fixtures and release packaging verification.
- [ ] Document unsupported capabilities and avoid universal claims.
- [ ] Obtain human approval before publishing repository or package.
